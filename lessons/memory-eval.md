# 教训：记忆评测的度量、对照与口径

来源：一个内部场景里约两周的小样本经验，只留不依赖内部背景的通用结论。关联 [plan](../plans/team-memory-quality/README.md)、[essay 03](../essays/03-same-session-leakage.md) 与 #17。条目格式：现象、原因、做法。

## 题和数据

相关 issue：[#28](https://github.com/yaodiff/memory-lab/issues/28)。

- **同会话事后更新的页会让记忆看起来有用。** 现象：有无记忆的差距大半来自这类页，换成页面来自别的会话、纠正后没再更新的「干净 case」，差距几乎消失。做法：评测只用干净 case，或把两类分开报告。
- **评测题的答案可能被采集会话写进记忆。** 现象：记忆里出现了和评测答案一样的页，评测分数被抬高。做法：评测与采集会话不进记忆；评测任务显式设置记忆截止时间。
- **坏题会把差距冲平。** 现象：目标页不适用或根本找不到的题，让有无记忆看起来一样。做法：先审题，再比较方案。
- **标注错会低估基线。** 做法：标注发现错误时先重算基线，再比较方案。标注是模型做的时要写明。
- **别用空环境构造题。** 现象：空环境里的首条请求和真实被纠正的点对不上，结果不可信。做法：用真实会话、真实 query，在纠正前一刻切开重放。

## 对照与口径

相关 issue：[#29](https://github.com/yaodiff/memory-lab/issues/29)。

- **和同时段的线上版本对照。** 现象：白天索引在变，上午看到的提升到下午就没了。做法：每个方案都带一个同时段的线上对照。
- **评测里的 Skill 或工具版本是变量。** 现象：评测脚本每次拷贝最新版 Skill，前后对比不再成立。做法：固定评测读到的版本；只评生产实际使用的版本。
- **离线预检会高估真 Agent。** 现象：让模型扮 Agent 填参数、翻目录，能做到的比例远高于真 Agent。做法：离线只做预筛，结论要在真 Agent 上取。
- **事先写门槛。** 做法：把通过线在看结果前写下来；小样本里几个点的差异测不出，要写明测不出。
- **次数和比例不要混。** 现象：用「至少搜一次的比例」说搜索没变多，实际平均次数变多了。没有分母的次数不叫比率。
- **取数默认值要复核零值。** 现象：参数为零被当成默认值，报告「某天起事件为零」。做法：出现突然归零时先核对取数参数。
- **评测流量会污染线上指标。** 现象：我们自己的评测占了一天里绝大多数检索，把采纳率拉偏。做法：评测流量打标，指标分母排除。
- **用采纳数衡量页面质量会得到噪声。** 现象：采纳主要由曝光量决定，且几乎没有负反馈。做法：先固定曝光再比较，或用离线判官加人工校准。

## 判官

相关 issue：[#27](https://github.com/yaodiff/memory-lab/issues/27)。

- **判官要写明是谁。** 做法：模型判官、子 Agent 复核都不叫人工抽查；人工只指真人逐项判定。
- **同族判官共享偏差（待验证）。** 现象：两个同族判官的结论经常一致但都偏宽；自查与独立复核差距明显。做法：关键门槛用独立复核，定期用少量人工校准，一致率低就重写判官。
- **判官之间的一致率本身要报。** 做法：金标与审计之间一致率不高时，不要用小数点后的差异比较方案。

## 检索指标

相关 issue：[#21](https://github.com/yaodiff/memory-lab/issues/21)、[#30](https://github.com/yaodiff/memory-lab/issues/30)、[#16](https://github.com/yaodiff/memory-lab/issues/16)。

- **相关度下限只挡无关，不挡「相似但错」。** 现象：下限能挡掉明显无关的结果，但相似度中等的错误结果仍排第一。做法：下限之外要有拒答门控或对原文的核对。
- **搜到和用上是两件事。** 现象：搜到基本会照做；读到不遵守的最大类是原文没进上下文。做法：分别度量触发率、命中率、遵守率。
- **触发时机和检索质量是两个瓶颈。** 现象：改 Skill 的写法能改变触发，却改不了「搜了也搜不到」的那一批题。做法：对两批题分别归因，别把一个数字归给两件事。
- **严格门槛没过却上线，要明说。** 做法：写清哪条门槛没过、为什么仍然上线、上线后看什么指标。
