# 教训：记忆的写入、整理与批量改写

来源：一个内部场景里约两周的小样本经验，只留不依赖内部背景的通用结论。关联 [plan](../plans/team-memory-quality/README.md) 与 #17。条目格式：现象、原因、做法。

## 批量改存量页

相关 issue：[#20](https://github.com/yaodiff/memory-lab/issues/20)。

- **先抽检小批，再放量，保留回滚。** 现象：一批改写写完才抽检，错误率超线，只能整批回滚。做法：先小批、设错误率门槛、过线再扩大；每次写入前备份。
- **门槛判定和写线上不要分属两条指令。** 现象：执行者先收到「写线上」，后收到「抽检未过线」，已经写了。做法：把门槛写进同一条任务，未过线时默认不写。
- **模型同时满足多条约束会悄悄丢东西。** 现象：要求「不升级、不降级、不删名字」时，模型会删结构段、改配置名、把「建议」写成「已确定」，改反了又出现反向降级。做法：约束拆开，结构用程序校验（章节、引用、标题形态），不靠提示词保证。
- **重写页面容易丢引用与依据。** 现象：整合或改写后，依据和代码引用被压缩或截掉。做法：引用单独成段并由程序核对前后数量；丢引用时放弃本次写入。
- **整批改写的是「没变的邻页」时，会反复改写。** 现象：没变的页随别的页进同一块，被改写后标成已变，下一轮又进块。做法：只写回本轮确实变了的页。

## 从纠正到规则

相关 issue：[#19](https://github.com/yaodiff/memory-lab/issues/19)。

- **一次纠正多数只对当次有效。** 现象：把单次纠正自动提炼成通用规则，样本外大多数不该写。做法：不自动写回；改成只判不写，把「该学没学」的清单当检索考题。需要写时，要求不同日子重复被纠正，或原话里明确要求以后照做。
- **只看纠正那一句会误判。** 现象：用户常在几分钟内自己改口，页面记的正是改口后的决定。做法：判定时带上后续对话，并要求摘出改口的原话。
- **别把 Agent 或框架注入的消息当用户纠正。** 现象：工具提示、摘要注入、技能模板都曾被当成用户输入。做法：抽取前过滤注入内容。
- **别把进度写进记忆。** 现象：状态节被填成分支、构建、待验证。做法：模板里把状态限定为决策状态；纠正写回里明确不写进度。

## 合并与标准

相关 issue：[#23](https://github.com/yaodiff/memory-lab/issues/23)、[#24](https://github.com/yaodiff/memory-lab/issues/24)。

- **规范的重复，多数不是字面重复。** 现象：两两去重效果很差，大多回滚。同一件事被拆成很多互补的碎片。做法：按主题整合，让整理模型可以核对代码，矛盾以代码为准。
- **整合提示词要与准入门槛一致。** 现象：提示词要求「并集不删」，门槛要求「少而精」，结果是多主题巨页。做法：整合与拆分的规则和门槛对齐；超长页按触发场景拆。
- **不同类型的页分别定标准。** 现象：一个统一的「有用」标准会把决策写成规范。做法：规范、经验、决策各定准入条件；功能设计细节不进规范。
- **合并后的保留页不要再被整页下线。** 现象：门槛把保留页当普通页判，牵连并入的条目。做法：门槛判定时识别并排除保留页。
- **整体重写提示词只会让模型少写。** 现象：值得留的比例几乎不变，还丢有用条目。做法：定点改规则，精度靠写入后的整理。

## 配置与运行

- **提示词的副本要有下发机制。** 现象：每个空间存了提示词副本，改了默认值线上不生效。做法：改提示词同时要有批量下发或版本比对。
- **夜间任务的内存状态在重启时丢失。** 现象：发版重启清零计数，一批空间当晚漏做维护。做法：状态落盘，发版后核对漏跑。
- **发版重启会打断正在跑的整理任务。** 做法：截止前不开新块，发版避开夜间窗口。
- **改标签、索引字段时覆盖所有空间。** 现象：标签只补了一个空间，其余空间的不指定类型的搜索被事件类页占满，持续约一天才发现。做法：改索引字段时用全空间探针验证，不只验证试点。
- **健康检查依赖的日志行会被别的刷屏吞掉。** 现象：同机的另一个服务刷屏，发布健康检查误判失败并回滚。做法：健康检查看状态而不是日志里的特定行。
- **模型额度与并发。** 现象：加并发反而更慢，因为单账号限流。做法：先看限流再加并发；批量任务与线上增量任务分开额度。
- **机器会重启，临时目录会清空。** 做法：备份、脚本、报告放持久目录，满盘前先清理，备份写不进时暂停写入。

## 授权与范围

- **把反问当同意会越界。** 现象：用户问「是不是可以扩散到全部」，被执行成了全部。做法：反问需要明确回答才能扩大范围。
- **子任务等不到回复时，默认值不能是破坏性的。** 现象：子 Agent 按默认隐藏了超出批准范围的页。做法：等不到回复时默认不动。
- **叫停之后的合并也要停。** 做法：叫停时同步关掉相关 MR 与发布。
- **判官都是模型时，抽检不能叫人工抽查。** 做法：在文档里写明是谁复核的。
