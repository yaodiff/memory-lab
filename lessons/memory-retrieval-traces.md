# 教训：何时查记忆，以及用什么去查

来源：内部小样本的一次用户会话复盘和一次编码评测复盘。

## 用真实轨迹区分没搜、搜偏和没用

- **Does not work**。在复盘到的编码任务里，首轮照着笼统任务描述搜业务，两道题都没直接找到对口页。后续用具体对象和动作查，有些已经存在的实现约定和验证经验才派上用场。用户会话复盘也见到短查询被同名对象带偏，以及正确页已经在首位却没被采用。先核对 Agent 在哪个步骤发起检索、当时知道什么、返回什么、最后有没有用。
- **Works**。两次复盘都看到对口页在合适的检索之后被读到并用于后续动作。处理带需求链接的编码任务时，先读需求取得上下文，再按具体仓库、函数、字段或动作拆开查。对于已经入库的知识，优先解决何时搜、拿什么去搜。用户复盘中，一部分当时未命中的内容直到事后才入库。一周样本里，按同一目的合并后的搜索约六分之一提供了实质或较弱帮助，决定何时保存和何时检索可以分别检查。
- **Inconclusive**。编码评测两组的运行配置不同，无法把评分差异单独归因到记忆。两次复盘也各有内容缺口与时效问题，无法据此估计查询改法对所有任务的收益。
