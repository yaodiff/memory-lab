# E019 复验 E009：关系候选融合与任务上下文锚定

- 结论：**Works**。上下文锚定提高了合成题在等阅读预算内找齐证据的比例。
- 日期：2026-11-24
- Issue / PR：[#85](https://github.com/yaodiff/memory-lab/issues/85) / 本 PR
- 来源：[E009](../E009-typed-relation-expansion/README.md)、[#64 上下文锚定](../../plans/plan-context-anchored-recall.md)、[Hindsight 源码](HINDSIGHT.md)
- 交接：无

## 假设

有出处的图链接可以让独立图路补足稠密和关键词候选。可从任务上下文定位的实体能给读者补充对口证据。对照看相同阅读预算内找到任务必需的两页，以及是否混入错对象或错动作的可执行信息。

## 做法

[主实验预登记](PREREGISTRATION.md) 在 [`27cc847902b2`](https://github.com/yaodiff/memory-lab/commit/27cc847902b2) 冻结。[配置](config.json) 固定模型版本、夹具摘要、统计规则和预算。使用 120 道完全合成的双页题，四个难点各 30 道，共十个领域模板，每题最多读六页。E009 另按原生长度报告追加或重排结果。每条图边须有匹配其类型与端点的来源记录，1,420 条通过，120 条无出处的测试边全部排除。

A 为稠密与关键词 RRF 全局搜索。B/C 复现 E009 的一跳追加及原始分数加权逻辑，使用合成全局榜单与弱相关替代口径。R 用交叉编码器重排两路融合，H 在同一预算与重排器下加入独立的图路。X 从已有任务上下文解析实体，单列它的直接挂接页，保留原全局前三，再从实体栏和全局榜单补足。Hindsight 当前 PG 默认图路是有界邻接展开，另有时间路的多跳传播。H 借鉴其多路融合，用两个传播步处理本实验的有出处页面边。 [Hindsight 机制与差异](HINDSIGHT.md)

### 复现

在实验目录下运行。固定的 ONNX 图和 tokenizer 可从 [稠密模型](https://huggingface.co/Xenova/paraphrase-multilingual-MiniLM-L12-v2/tree/2c4055b12046) 和 [交叉编码器](https://huggingface.co/Xenova/ms-marco-MiniLM-L-6-v2/tree/a09144355ade) 获取。各自的 `onnx/model_quantized.onnx` 保存为模型目录内的 `model.onnx`，同目录放 `tokenizer.json`。资产目录下使用 `embedding`、`reranker` 两个子目录。判官地址为具有 `codex/gpt-6.2-sol` 路由的 Chat Completions 接口。命令只向该接口送合成数据。

```sh
python -m pip install numpy==2.4.4 onnxruntime==1.24.4 tokenizers==0.22.2
python -m unittest discover -p 'test_*.py'
mkdir -p "$RUN_DIR"
python fixture.py > "$RUN_DIR/fixture.json"
python retrieval.py --assets "$ASSETS" --out "$RUN_DIR/orders.json" --threads 6
python judge.py --orders "$RUN_DIR/orders.json" --out "$RUN_DIR/judge" --endpoint "$JUDGE_ENDPOINT" --workers 10
python summarize.py --orders "$RUN_DIR/orders.json" --judge-dir "$RUN_DIR/judge" --out "$RUN_DIR/results.json" --commit 27cc847902b2
```

- H 将两页同在候选上限 12 条内的题数从 R 的 85/120 提到 106/120。到了前六条，只剩 2 道增益。直接拿 H 对比 A 会得到 +13.3 pp，其中大部分也能由无图重排取得。

请求模型 `codex/gpt-6.2-sol`、解析模型 `gpt-6.2-sol`，180/180 个独立批次成功。两轮在找齐、前三错页、前六错页三项的逐题判定上，每个臂都是 120/120 一致，也与构造金标逐题一致。各臂三项的重复判官 95% 区间均为 [0, 0] pp，绝对半径 0 pp。该测量只覆盖这份短文本夹具和这一评判口径。模型回执合计 1,492,310 token，含 1,450,929 输入和 41,381 输出。

### 内部冻结对照摘要

一个小规模只读回放使用冻结搜索结果和有可核验来源的关系。定向题中，本地无图重排找到了更多前五目标页，独立加图未再增加命中。冻结问题没有保存搜索前的任务实体上下文，严格上下文栏未触发。新增候选缺少统一错页标签，无法比较各臂的实际错页率。内部数据、逐题结果和详细计量保存在本机。

## 结论

有可用任务上下文、且挂接覆盖足够时，实体栏把补充页带进相同的六页阅读预算。H 在这份夹具上扩大了候选覆盖，但同样重排之后没达到预登记要求的前六找齐增益。补充对照找到了 E009 旧方法的局部机会。追加能把有出处的实体带进扩大的阅读范围，且收益依赖首轮种子。

## 没覆盖的

六臂前六错页率均为 100%，二元护栏已饱和。这轮支持 X 的证据覆盖增益。它没有量出更低的错页暴露，且 X 的错动作页增加。合成夹具的实体别名是预先登记的，挂接准确率来自构造证据，覆盖率比线上能否取得高质量任务上下文更容易验证。真实的锚点歧义、关系长期维护、模型在任务执行中是否采纳正确证据，以及线上时延均未测试。
