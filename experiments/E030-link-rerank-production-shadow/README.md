# E030 出链相关性重排的生产影子验证

- 结论：**Works as a safe shadow rollout**（影子日志齐备、用户可见返回零扰动、附加耗时可忽略；线上效果与是否转正式流量仍待观察）
- 日期：2026-11-25
- Issue：[#93](https://github.com/yaodiff/memory-lab/issues/93)
- 来源：自有生产环境的固定 10 题 off/shadow 探针；离线效果见 [E022](../E022-existing-link-reranking/README.md) 与 [E025](../E025-rollout-checkup-four-arm-replay/README.md)
- 交接：影子配置仅对一个内部空间开启，设有定时回收结论

## 假设与做法

[E022](../E022-existing-link-reranking/README.md) 的离线回放显示，只重排搜索结果页已有的普通出链（按问题词覆盖度、更新时间和原链序稳定排序，不新增查询、不扩候选）能改善多页证据找齐。上线前需要在生产验证三件事：默认关闭时行为不变；影子模式只记录建议排序、绝不改变返回；重排计算的真实开销可忽略。

改动先经离线 150 题冻结回放复现（多页找齐 34→37/60、单页不退、SQL 计数不变）和服务包测试，再合入并发版。生产配置从旧版本升到新版本时只新增一个影子开关，且只对首个试点空间设为 shadow；既有的摘要灰度空间名单和另一路检索融合影子配置均原样保留、未改一字。用固定 10 道题（3 道离线增益题加 7 道等距抽取的单页对照）在同一生产版本上各跑 off 与 shadow 两阶段，请求带测试流量标记，按日志实例核对影子事件、共同命中出链顺序和耗时。

## 数据

| 观察项 | off 阶段 | shadow 阶段 |
| --- | ---: | ---: |
| 请求成功且命中记忆页 | 10/10 | 10/10 |
| 在生产实例日志中找到对应记录 | 10/10 | 10/10 |
| 出链重排影子事件 | 0/10 | 10/10 |
| 既有检索融合影子事件 | 10/10 | 10/10 |

- **用户可见返回零扰动**：两个阶段共同命中的 49 个页面上，实际返回的出链顺序 49/49 完全一致——影子只记录建议，不参与响应。
- 影子算法共记录 96 个「建议序与原序不同的槽位」用于离线评估，每请求可见候选 3–35 个；这些差异没有下发给任何调用方。
- 重排与差异构造的日志字段耗时中位 **0.166 ms**，范围 0.048–0.425 ms。
- 两次独立实时请求的主召回集合 9/10 一致、完整主召回顺序 7/10 一致；这部分差异来自在线检索的实时性与两次采样，不是影子重排造成的（返回序已由 49/49 出链一致与 shadow 只读路径隔离）。
- 配置发布经独立审批后全量生效，并通过全流量质检；发布前后其他配置项保持不变。

跨空间对照：在第二个业务空间的 76 题重放里，同一改动是进 0 出 0（[E025](../E025-rollout-checkup-four-arm-replay/README.md)），因为该空间绝大多数种子页出链不超过五条、漏召金标页也不在出链截断位置。这说明该改动的收益依赖页面出链密度与摘要质量，不能从首个空间直接外推。

## 结论与是否采用

- **影子机制与安全性验收通过，保留 shadow 继续观察**：零返回扰动、亚毫秒开销、日志字段只含页标识对、候选数与耗时。
- **尚不能据此声称生产效果提升**：10 题是固定安全探针，不是效果样本；离线的多页增益（E022）需要用影子日志在真实流量分布上复核。
- **暂不切为正式排序（on）**：等观察窗回收真实流量上的出链变更率、多页覆盖与延迟后再决定；第二个空间在摘要回填和出链变密之前没有离线收益，不为它单独开启。

## 没覆盖的

固定 10 题样本太小且含刻意挑选的增益题，不能估计总体收益。off 与 shadow 之间隔着配置发布和两次实时检索，主召回本身有轻微不可复现性。没有量 Agent 侧的点击、跟读或采纳变化，也没有做长时间窗的性能分位统计。影子日志的后续离线效果评估结果在本条目写作时尚未回收。
