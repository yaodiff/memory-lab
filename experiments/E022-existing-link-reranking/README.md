# E022 仅按问题重排已有出链

- 结论：**Works**（对固定结果附带的证据，多页找齐有小幅收益，适合进一步影子验证）
- 日期：2026-11-25
- Issue：[#89](https://github.com/yaodiff/memory-lab/issues/89)
- 来源：自有场景小样本，复用 [E021](../E021-heldout-retrieval-fusion/README.md) 的留出题和融合结果
- 交接：无

## 假设与做法

主结果固定为向量加 BM25 的前五。比较维持现有出链顺序、按更新时间排序、按问题词法相关性排序，再以共享实体扩候选做诊断。指标是主结果与附带的可读页去重后能否找齐，附链额度保持一致。

离线比较用标题和摘要词法分。实现回放把改动缩小到已有普通出链，读取原批查结果，通过原有可见性过滤后，按标题和摘要覆盖的不同查询词数排序。实体反链保留原行为。实现回放在本地数据库夹具上运行实际附链函数，与离线比较逐题对账。

## 数据

| 附链策略 | 多页找齐 |
| --- | --- |
| 只计主结果 | 30/60 |
| 原附链 | 34/60 |
| 普通出链按更新时间排序 | 36/60 |
| 普通出链按问题排序 | 37/60 |
| 词法排序并扩大到共享实体候选 | 37/60 |

词法排序比原附链高 5.0 个百分点，配对 95% CI **[0.0, +10.7]**。单页题在实现回放中维持 79/84。共享实体扩候选在相同展示额度下对多页没有净收益，有题找齐也有题丢失，并带回更多无关页。

实现回放的 150 题中，两臂新增 SQL 查询数为零。离线词法附链本机 P99 低于 1 ms。另一份实现回放中，仅排序的本机 P99 略高于 1 ms。两个计时覆盖了不同实现，均为本机读数。

## 结论与边界

优先在已有候选内排序，固定展示额度时，候选变多也可能挤掉必需页。按更新时间已经拿到大部分观测增益，词法对它的优势仍小。本次只验证可读证据覆盖，实际请求的数据库耗时、权限路径和 Agent 跟读需要单独验证。
