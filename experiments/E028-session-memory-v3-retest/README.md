# E028 会话到记忆主链路的真实模板复测与上传假成功根因

- 结论：**Works for the minimal prototype**（原窗与单纯补闭环窗均为 0/4；补窗加最小实体重判原型后 4/4 产出合格经验页，且 5 个原够用案例零重复、零泄漏）；同时定位到上传侧一个静默假成功缺陷
- 日期：2026-11-25
- Issue：[#93](https://github.com/yaodiff/memory-lab/issues/93)
- 来源：自有场景小样本；4 个漏抽案例做三臂对照，5 个原够用案例做回归，共 22 组真实模型运行
- 交接：修复已拆成草稿合并请求，停在合并前等待审批

## 假设与做法

此前用小模型做的 13 个真实已解决会话审计发现 5 个够用、4 个未抽、4 个抽不全，并假设主要断点是窗口碎片缺少上线闭环、部分止于上传入口。但小模型正文质量不能代表生产抽取器。本轮用生产同版抽取代码、真实新版抽取模板、严格摘要/叶实体写入闸和生产同款大模型，在离线快照（保留数万页索引与完整实体子树，仅把生产读写换成内存镜像、代码读取绑定到不可变提交）上复测 4 个典型漏抽案例。

三臂：原始增量窗；只机械补入含上线读回的闭环回执；补窗加一个最小修复原型（相关子实体排序、写入闸在父子树找不到叶实体时回退到全空间相关叶实体、仅对闭环窗追加四行路由重判说明）。另对 5 个原本够用的案例跑机械边界检查与两轮回归，并注入三类负样本：闭环回执二次重放、明确未验证的未来改造设想、单次临时个人需求。上传侧对两个确定没进来源表的会话做逐跳只读溯源，排除会话类型过滤、归档时机、内容过滤、服务端准入和归属裁判等候选。

## 数据

**四案例三臂结果**：

| 臂 | 合格经验页产出 |
| --- | ---: |
| 原始增量窗 | 0/4 |
| 仅机械补闭环窗 | 0/4 |
| 补窗加最小修复原型 | 4/4 |

原始窗暴露三个此前小模型未见的代码级卡点：

1. **实体字典序截断**：喂给模型的实体标题列表硬截断前 300 条，而空间有约 1,963 个活跃实体，按标题排序后前 300 只覆盖符号与 A–D 开头，约 85% 的活跃叶实体不可见；叠加严格叶挂载闸只在被命中父实体的子孙树内找叶实体，两个案例的 4 篇有效候选全部因「找不到可挂载子实体」被挂起误杀。
2. **闭环被路由降级或静默丢弃**：通用路由把「已发布/已合入」的闭环回执压成无代码引用的事件页，事件构造不经过决策与代码核证，且只追加章节、不刷新旧事件标题（出现上线成功后标题仍永久停在「受阻」）；另有两案被空间静态规则误判为「描述系统现状/记忆系统自身设计」而返回空条目。单纯补窗因此仍是 0/4。
3. **取代校验失败后被硬丢**：一案写出高质量决策页并提议取代旧页，校验认为只应按范围补充而非整体取代；新版抽取分支在取代被拒后直接把成品挂起丢弃，而旧版分支本会降级为更新。

最小原型的 4 篇经验页全部通过摘要闸与叶实体挂载，人工逐篇核验根因、可执行修法、实测环境边界和无范围幻觉均合格；瑕疵是两处倾向新建概念实体而非复用既有叶实体、一处复制了内部蛇形标识命名，已纳入正式修复设计。

**回归**：5 个原够用案例的 25 项机械边界断言全部通过；原始模板回归与原型回归各跑 5 案，共 10 次对抗重放中重复建页 0/10、未验证设想或临时需求泄漏 0/10；两次合法更新都只改既有事件页。

**上传溯源**：两个缺失会话都在客户端工作空间归属阶段被本地排除，从未发出网络请求。它们的工作目录本身没有空间注册清单，归属逻辑在 `$HOME` 之上时刻意拒绝推断（此前防跨空间串流的保护），而工具调用读到的空间仓库路径不在工作目录祖先链上、不被扫描。更严重的是被排除时单会话命令以退出码 0 成功返回、不写排除记录，监听进程据此推进游标并写入虚假的「已上传」日志，诊断命令又因查不到排除记录误报「等待上传」，形成空转循环。另发现本机定时补传任务当天持续网络不可达，但这只影响已归属会话的封口，不是这两个会话零发包的原因。

## 结论与是否采用

- **采纳最小修复组合**：机械闭环补窗必须配合实体供给/路由修复才有效，单纯补窗被否。正式修复不放松任何准入与写入闸，加幂等闭环账本、实体相关性排序与全空间叶实体回退、闭环专用路由说明、取代被拒降级为按范围更新、受阻事件标题可刷新。
- **上传侧采纳「先修假成功、再加受控归属兜底」**：第一步把无法归属写成永久排除并返回结构化状态，绝不写假成功；第二步用显式目录绑定/手动指定空间，以及「全部工具路径唯一命中一个已注册空间」的反推来救回此类会话，命中零个或多个空间仍拒绝。`$HOME` 防串流边界不回退。
- 两项修复均已形成草稿合并请求，检查与离线回归通过，但按仓库红线停在合并/部署审批前；本实验本身不宣称线上已修好。

## 没覆盖的

样本只有 4 个漏抽案例加 5 个回归案例，4/4 不能估计总体漏抽修复率。离线镜像冻结了某一时点的页面与实体状态，真实线上索引、并发写入和模型版本漂移未覆盖。原型结果来自一次真实模型运行，没有重复运行刻画模型方差。上传根因在一台开发机的特定客户端版本上逐行证实，其他安装形态未普查。token 消耗按严格合并口径（含编排会话与一次缓存失效）超过原定预算，实验模型单独口径约为预算的三分之一。
