# E020 实体整理为什么没改善检索

- 结论：**Does not work**（在当前检索路径中，单靠整理实体结构没有提高前五找齐率）
- 日期：2026-11-25
- Issue：[#89](https://github.com/yaodiff/memory-lab/issues/89)
- 来源：自有场景小样本，结合历史回放与只读实现核对
- 交接：无

## 假设与做法

如果补实体挂载、给关系补出处、拆分宽泛的父实体能改善检索，整理后前五条结果应更常覆盖一整组必需证据，尤其是多页题。用同一小样本比较整理前后，再检查挂载、检索排序、附链和评测各环节，定位结构变化在哪里可能影响结果。

## 数据

- 60 题中有 35 题可以登记证据金标。整理前后，前五找齐率均为 18/35。按主证据组拆分，单页题找齐 17/21，多页题仅 1/14。
- 其余 25 题无法建立金标，其中 17/25 缺少知识库内容，8/25 需要现场或实例数据。60 题中另有 9/60 的证据已在较宽候选池里，但前五没有整组找齐。
- 在 28 张前五缺失的必需页中，约七成能由前五结果经直接链接或共享实体到达。共享实体的典型展开量在百页量级。

## 结论

检索服务在确定主结果前没有按实体或关系生成候选，相关链接只在排序后附带。拆分时给页面追加子实体挂载，同时保留父挂载，父入口仍很宽。旧评测的多页题少，错页计数也无法判断一整组必需证据是否找齐。图里能找到一条路，还需要排序或阅读过程实际沿这条路取回证据。

后续将召回、固定候选内排序、附链和最终采纳分开测，并单列多页题。检索融合见 [E021](../E021-heldout-retrieval-fusion/README.md)，固定主结果的附链见 [E022](../E022-existing-link-reranking/README.md)。

## 没覆盖的

宽候选池和前五结果来自不同时间点和接口，逐题归因只给排查方向。没有量化挂载本身的正确率、Agent 跟读或实际采纳，也没有测完所有缩小父入口的策略。
