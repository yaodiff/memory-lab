# E004 meta 优化的记忆读写提示，换到没见过的世界还赢通用版吗（合成）

- 结论：不行（按预设判定线：优化后比通用低 0.21。但搜索选中的「优化后」就是通用提示本身，差距全部是同一提示两次运行的噪声，见下文）

- Issue / PR：[#34](https://github.com/yaodiff/memory-lab/issues/34) / [#41](https://github.com/yaodiff/memory-lab/pull/41)
- 来源：业界论文 [Self-Improving Memory](https://facebookresearch.github.io/RAM/blogs/self_improving_memory/)（读后见 [第 04 篇](../../essays/04-self-improving-memory.md)）
- 交接：无

## 假设

论文报告：让模型改写自己的 LOAD / OFFLOAD 提示并保留最高分版本，三项任务平均从通用提示的 36.1 涨到 56.0。但「最佳」是在被评测候选里选出来的，没有「选完冻结、再到没参与选择的任务流上测」的数。

本实验问：**在一个训练世界上 meta 优化并冻结的提示，到分组名和隐藏单位都换掉的新世界上，比通用提示高多少？** 只做论文第一步（harness 优化），不做微调。

判定线（运行前写入 [config.json](config.json) 并提交，指标是 3 个测试世界上全部 14 题准确率的均值）：

- **行**：优化后 − 通用 ≥ 0.10，且 3 个世界里至少 2 个优化后 ≥ 通用。
- **不行**：优化后 − 通用 ≤ 0.02。
- **说不清**：其他情况。

## 做法

**数据**（全部由 [run.py](run.py) 按固定种子生成，无外部数据）：每个「世界」有 5 个商店分组，每组订单的价格字段是「分」或「元」、数量字段是「件」或「打」，四种组合都出现。每题给出一行原始字段（价格、数量），问订单收入是多少元。单位不在题面里，只能从前面题目的反馈推出来，所以第一次见到的分组基本靠猜（约四分之一），重复见到的分组靠记忆。第 9 题起，有一个分组的价格单位悄悄翻转（分 ↔ 元），模仿论文基准的「相变」，看记忆能不能从「已证实」改回来。每条任务流 14 题，按与标准答案相差不超过 0.5% 判对，不用模型判官。

**流程**：每题开一个空上下文。LOAD 调用里给出 LOAD 指令 + 整个记忆目录 + 题目，要求最后一行 `ANSWER: <数字>`；然后把对错和标准答案反馈给模型，OFFLOAD 调用里给出 OFFLOAD 指令 + 当前记忆 + 本题和反馈，要求返回 JSON 整体替换记忆目录。记忆总长封顶 2000 字符，超出截断。和论文的差别：记忆整份注入，不是模型用文件工具按需读；没有工具调用。

**实验组**

| 组 | LOAD / OFFLOAD | 来源 |
| --- | --- | --- |
| `no_memory` | 无记忆，只答题 | 下限 |
| `generic` | 论文 Figure 7 的通用版，去掉「用文件工具」几个字（本实验没有文件工具） | 论文 |
| `summary` | 论文 Figure 7 的人写「摘要」版原文 | 论文 |
| `skill` | 一份技能库式提示（触发条件 + 步骤） | 我们写的种子 |
| `transplant` | 论文 Figure 1 Database 任务搜出来的提示照搬（含 GUARDRAILS.md、CONFIRMED/UNTESTED、IF→THEN；只把 ≤ 和 → 换成 ASCII） | 论文，未经本实验选择 |
| `optimized` | 种子池 = generic / summary / skill；训练世界上每个候选跑 2 条任务流，取前 2 名让 meta agent 读轨迹改写，共 2 轮（4 个改写），按训练世界平均分选最高者冻结 | 本实验搜索 |

meta agent 被告知「以后的任务流里分组和属性可能不同，不要把具体分组的事实写进指令」。搜索只看训练世界；3 个测试世界各跑 1 条任务流，分组名、单位分配和题目都不同。

**模型和命令**：任务 Agent 和 meta agent 都是 Claude Code CLI `2.1.325`，请求 `haiku`，每次回执解析为 `claude-haiku-5-5`（与论文「同一模型」的设定一致，模型不同）。在本 PR 分支提交 `a5782f4`（判定线已写入）上运行：

```bash
python3 experiments/E004-meta-optimized-memory-prompts/run.py \
  --model haiku --workers 10 --out experiments/E004-meta-optimized-memory-prompts/runs/full
```

运行窗口 `2026-11-20T07:52:25Z` – `2026-11-20T08:18:48Z`（UTC）。任务调用 854 次（答题 448 + OFFLOAD 406），meta 调用 4 次，无重试、无中途改代码。448 次答题回执的解析模型全部是 `claude-haiku-5-5`；OFFLOAD 和 meta 调用的解析模型名没有记录（runner 的疏漏）。CLI 回执里的费用估计合计约 0.77 美元，不是账单。原始轨迹和汇总：[logs.jsonl](runs/full/logs.jsonl)、[results.json](runs/full/results.json)。

| 候选 | 父本 | 训练分 |
| --- | --- | ---: |
| generic | — | **0.643** |
| meta-i1-1 | skill | 0.607 |
| skill | — | 0.571 |
| meta-i2-0 | generic | 0.571 |
| summary | — | 0.500 |
| meta-i1-0 | generic | 0.500 |
| meta-i2-1 | meta-i1-1 | 0.357 |

4 个 meta 改写**没有一个**超过最好的种子，按规则选中的是 `generic` 本身，所以测试里的 `optimized` 和 `generic` 是同一份提示、各自独立跑一次。meta agent 的改写里有两份自己提出了「区分反馈证实过的和未验证的规则」（和论文的 CONFIRMED / UNTESTED 同向），训练分分别是 0.500 和 0.571，没有赢。

### 测试（3 个没参与选择的世界，各 1 条任务流）

| 组 | 全部 14 题 | 重复见到的分组 | 翻转后的题（共 6 题） | 没给出答案 | 三个世界 |
| --- | ---: | ---: | ---: | ---: | --- |
| no_memory | 0.167 | 0.192 | 0.000 | 0 | 0.214 / 0.143 / 0.143 |
| generic | **0.571** | 0.875 | 0.389 | 3 | 0.714 / 0.643 / 0.357 |
| summary | **0.571** | 0.863 | 0.278 | 5 | 0.714 / 0.500 / 0.500 |
| transplant | 0.429 | 0.724 | 0.000 | 8 | 0.500 / 0.357 / 0.429 |
| optimized（= generic 再跑一次） | 0.357 | 0.605 | 0.278 | 4 | 0.429 / 0.571 / 0.071 |
| skill | 0.333 | 0.613 | 0.111 | 1 | 0.571 / 0.357 / 0.071 |

「重复见到的分组」「翻转后」两列是三个世界的均值（各世界分母不同）。448 次答题里有 1 次按 0.5% 容差判对、但与标准答案不完全相等（580.08 对 581.04）；按严格相等重算，generic 为 0.548，其余组不变，结论不变。

**一个值得记的失败**：第三个世界里，同一份通用提示一次得 0.357，另一次（`optimized`）只有 0.071。后者在第 1 题被告知答案后，把「价格字段都是分」写成全局规则，之后 13 题答错 12 题：记忆里逐条记下了每次反馈和「多数反馈与规则冲突」，但规则本身一直没改，答题时照用。前者记的是逐分组的规则，就没有这个问题。

## 结论

- **按判定线记「不行」**：优化后 − 通用 = −0.21，低于 0.02。这条结论要和下一条一起读，不能当成「meta 优化有害」。
- **这次实验其实测不出 meta 优化的效果**：搜索没有找到比种子更好的提示，选中的就是通用版；同一份提示独立跑两次，三世界均值差 0.21，单个世界差到 0.29。论文用每个候选 5 次、评测 10 个种子，在我们这个规模（每臂每世界 1 条 14 题的流）上，噪声大于论文报告的任何一项提升。
- **照搬论文搜出的提示没有迁移**：`transplant` 比两次通用运行的均值低，翻转后的题全错，没给答案的次数最多（8 次）。它为另一个任务选出来，在这里没有证据说明有帮助。
- **值得保留的观察**：① 有记忆比无记忆高得多（约 0.17 → 0.36～0.57），说明任务本身能区分记忆好坏；② 搜索 4 个改写 0 个胜出，与论文 44 个里 37 个没赢同向；③ 「第一次观察写成全局规则、之后的反证只记不改」在同一提示下随机出现，这正是 [第 04 篇](../../essays/04-self-improving-memory.md) 说的「一次失败被写成永久规则」，也说明 IF 条件和依据状态值得写进记忆格式，而不只靠提示措辞。
- 对 [第 04 篇](../../essays/04-self-improving-memory.md) 的影响：「对幅度打折」的判断没有被推翻，也没有被这次实验证实；它只说明要看清这类提升，需要远多于这里的重复次数。

## 没覆盖的

- 规模太小：每臂每个测试世界只跑 1 次，搜索每个候选 2 次、2 轮、4 个改写。要分辨 0.10 的差距，至少需要每臂数十条任务流（**推断**，没有做功效计算）。
- 没有做论文的第二步（换回通用提示后微调），也没有 holdout 选择（这里在训练世界上选，再到新世界测，比论文更严）。
- 任务是一个人造的单位推断题，比 Continual Learning Bench 简单得多；记忆整份注入，模型不用文件工具按需读取，所以 LOAD 指令里「先读哪个文件」这类读序差异在这里测不到。
- 只用了一个小模型（`haiku`）做任务 Agent 和 meta agent；换更强的 meta agent 可能结果不同。
- 0.5% 容差导致 1 次把算错的答案判对，并给出了自相矛盾的反馈（「你答对了，正确答案是另一个数」）。影响很小，但后续应改成严格相等。
- 记忆封顶 2000 字符，部分候选在整个运行中频繁被截断（OFFLOAD 后截断次数：`skill` 36、`transplant` 23，`generic` 6），截断本身可能拉低了这些组的分数。
- OFFLOAD 与 meta 调用的解析模型名未记录。
