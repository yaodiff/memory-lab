# Plan：团队记忆质量治理（写对、搜得到、用得上）

## 背景与问题

团队记忆要帮到编码 Agent，要过三道关：[写对、搜得到、用得上](../essays/01-three-gates.md)。我们在一个内部场景里用大约两周集中治理了这三道关。这份 plan 只写通用做法、取舍和步骤状态，结论是粗粒度的，来自小样本，不代表通用结论。

总体状态：

| 关 | 状态 |
| --- | --- |
| 写对 | 改善明显，主要来自写入规则和写后检查 |
| 搜得到 | 改善很小。多数想法没有越过事先定好的门槛 |
| 用得上 | 搜到之后基本会照做，但「搜到」本身是瓶颈，这一关几乎没有单独改善 |
| 少被纠正 | 尚未证实，要等足够长的观察窗口 |

另一个发现：我们自己的评测设置多次高估或掩盖了效果。这些失败方式单独记在 [评测教训](../lessons/memory-eval.md)。

## 目标 / 不做什么

目标：

- 让 Agent 在真实开发中少被纠正，而不是让记忆条数更多。
- 把「哪些做法有效、哪些无效、为什么」写成别人可以复用的取舍。

不做什么：

- 不在 Lab 里放内部系统的名字、数字、样例和链接。内部明细留在内部文档。
- 不把内部小样本结论包装成通用结论。需要数字的结论，另开实验 issue，用合成或公开数据复现。
- 不在这份 plan 里决定产品改动。需要交接时，走 `handoff/` 的公开交接卡。

## 方案

分四块写：写入与整理、检索与触发、遵守、度量。每块写选择的做法、考虑过的备选和取舍。

### 写入与整理（写对）

选择的做法：

- 写入时要求证据：规则和决策要有用户原话或可核对的代码作依据，只有模型推测的条目只当线索。
- 把质量要求做成写入后的程序化检查（结构、引用、章节、标题形态），而不只靠提示词。
- 夜间整理按主题整合碎片，而不是两两去重；整合时让整理模型能直接核对代码，矛盾以代码为准。
- 批量改存量页之前，先抽一个小批次检查，设错误率门槛，放量时保留回滚。
- 不同类型的页分别定标准。准入门槛偏紧：跨任务、不知道就会做错、可执行可检查。

考虑过的备选与取舍：

- 整体重写提示词让模型一次写对。结果只是「少写」，值得留的比例几乎不变，还丢掉一部分有用条目。改为只定点改规则，精度靠写入后的整理。
- 把一次纠正自动提炼成通用规则并写回。样本外大多数不该写，放弃。改成只判不写，把「该学没学」的清单当检索考题。
- 两两去重式合并。同一件事往往拆成多条互补的碎片，不是字面重复，去重会丢内容或误合。放弃。
- 让模型整批重写存量页。同时满足多条约束时错误率波动大，还会悄悄删结构。放弃，改成加提示或程序化补丁。

### 检索与触发（搜得到）

选择的做法：

- 把「该搜的时刻」写进 Agent 一定会读的位置，而不是只写在正文里。
- 相关度很低的结果直接不返回，而不是保底返回前几条。
- 拒答门控（设计中）：低相关时仍返回，但标成弱相关；同时把平台类问题引到官方手册。

试过但没有越过事先定好的门槛的备选：

- 目录或索引让 Agent 自己翻、重新归类、按动作打标签做过滤、按场景分目录。
- 查询改写、查询规划、按仓库加权、意图搜、词法融合、模型重排。
- 让搜索工具多一个「这一步在做什么」的参数，或改参数说明。

取舍：附加模型功能收益小、延迟大。离线预检（让模型扮 Agent）会明显高估真 Agent 的行为，所以每个想法都要在真 Agent 上同时段对照，并事先写下门槛。

### 遵守（用得上）

- 搜到之后大多会照做。读到却不遵守的最大一类，是原文根本没进上下文，其次是看过没做。
- 结果里给原文而不是摘要，在受控对照里有效，在真 Agent 上差异不大。状态：未解决。

### 度量

- 评测用「干净 case」：页面来自别的会话，且纠正之后没有再被更新，否则会高估记忆的作用，见 [essay 03](../essays/03-same-session-leakage.md)。
- 评测要贴近生产：真实会话、真实 query、线上同一版本的 Skill，不用空环境构造题。
- 先写门槛再看结果；和同时段的线上版本对照，因为索引会随时间变化。
- 判官是模型时，必须写明是模型判官，不叫人工抽查；同一模型家族的判官可能共享偏差（待验证）。
- 没有分母的次数不叫比率。
