# M2 让 Agent 搜得到

[← 总览](README.md) · [GitHub milestone](https://github.com/yaodiff/memory-lab/milestone/2)

## 目标与退出条件


- 目标：Agent 在做决定的时刻去搜，并且搜到对的页。
- 退出条件：在真 Agent 上越过事先写好的命中率门槛，且触发率、命中率分开报告。
- 状态：未达成。想法很多，越过门槛的很少。

## Issue：触发率与命中率是两个独立瓶颈吗（[#21](https://github.com/yaodiff/memory-lab/issues/21)）

- 假设：「该搜时不搜」和「搜了也搜不到」是两个瓶颈，把触发时机写在必读位置只解决前者。结论：说不清。
- [x] Task：在工具说明里加「做决定前再搜一次」。结果：受控对照有效，真实会话没有定论（样本小）。
- [x] Task：把「交付前按动作逐个搜」写进 Skill 正文。结果：不行。原因：大量运行根本没打开那个文件。
- [x] Task：把同样的要求写进一定会读的位置（描述字段、项目入口文件）。结果：找到率有提升；违反率两个判官方向相反。说不清。上线时明确标注了严格门槛未过。
- [x] Task：加一个「这一步在做什么」的可选搜索参数；只改参数说明。结果：不行，真 Agent 几乎不填或仍搜业务词。
- [x] Task：把搜索写法改成中途检索、精简结果。结果：说不清，对照几乎无差别。
- [x] Task：把 Skill 瘦身、压缩后不重搜。结果：行，减少了重复搜索造成的拖慢。
- [ ] Task：#21 在公开任务上独立操纵指令位置与检索质量。

## Issue：目录、索引、归类让 Agent 自己翻（无 issue，已完成）

- 结论：不行（规范专用目录除外）。
- [x] Task：索引文件让模型翻；把「通用」类重新归类；按动作打标签后过滤；按场景分目录。结果：不行。离线预检高估，真 Agent 经常不翻目录，标签硬过滤丢掉原来能命中的结果。
- [x] Task：规范分级目录、三层目录（通用、仓库、业务）、截取最常用的一批必读。结果：不行。业务层比直接搜索差，截取后基本失效。
- [x] Task：「做事类别、领域，点开分组直接给原文」的规范目录。结果：行，唯一越过门槛的读侧方案，但对照不是严格同时段，真 Agent 的「完全遵守」差异不大。
- [x] Task：分发到个人目录让 Agent 都能用上。结果：放弃。重测发现规模被高估，用户也不支持。

## Issue：事件类页挤占检索结果（无 issue，已完成）

- 结论：行，附带一次回归。
- [x] Task：事件类页硬上限，超额时补搜其他类型；给索引加类型标签。结果：行，事件挤占消失，检索耗时下降。
