# M1 写入质量

[← 总览](README.md) · [GitHub milestone](https://github.com/yaodiff/memory-lab/milestone/1)

## 目标与退出条件


- 目标：新写入和存量的页达到事先写好的质量标准，靠写入时的检查保证，不只靠提示词。
- 退出条件：结构类缺陷在写入前被拦截；批量改写有演练过的回滚；纠正泛化的假设有结论。
- 状态：内部大部分达成，剩余是在公开或合成数据上的验证。

## Issue：写入要有证据与准入（无 issue，已完成）

- 结论：行（内部小样本）。
- [x] Task：规则和决策要求用户原话或可核对的代码作依据，只有模型推测的条目只当线索。结果：行。
- [x] Task：评测与采集会话不进记忆。结果：行，直接修复了答案泄漏。
- [x] Task：整体重写提示词让模型一次写对。结果：不行，只是「少写」，值得留的比例几乎不变，还丢有用条目。放弃，改为只定点改规则，精度靠写入后的整理。
- [x] Task：状态节只写决策状态，不写进度；经验页不写当次结果。结果：行。
- [x] Task：写完后单独做一次性细节检查。结果：行。把同样的规则直接塞进主提示词：不行，条目变少但缺陷占比几乎不变。
- [x] Task：在冻结会话上对比第三版增量写入模板与旧模板。结果：**Works**（内部小样本）。同一判官盲评下，已写入页面的平均忠实度从约八成满分提高到接近满分。新版写出的页更少，暂缓更多，可复用要点的总体覆盖率仍待核验。

## Issue：把一次纠正自动变成规则（[#19](https://github.com/yaodiff/memory-lab/issues/19)）

- 假设：多数纠正只对当次有效，单次纠正泛化不可靠。结论：说不清（内部倾向不行，待合成复现）。
- [x] Task：纠正后自动提炼规则并写回。结果：不行。写回前的 grounded 检查多轮都没同时达到「放行里坏的少、好的保留多」，样本外大多数不该写。放弃。
- [x] Task：冲突页自动加「用户纠正过」标注。结果：不行。原因：只看纠正那一句，没看用户几分钟后的改口。默认关闭。
- [x] Task：写回前检查用户后来有没有改口，并要求摘出改口原话。结果：行（初版拦得过宽，收紧后可用）。
- [x] Task：改成只判不写，把「该学没学」清单当检索考题。结果：行。
- [x] Task：复核纠正补写的对账判断和成页范围。结果：**Does not work**（内部小样本）。按分层抽检的对账判定计，约四成应改判。发现一次性授权被扩大成团队规则。评审建议仅在长期适用范围明确时直写团队规则，其他高影响纠正先进入人工审核。
- [ ] Task：#19 在合成纠正流上比较「首次纠正就写」与「重复或明确要求才写」。

## Issue：批量改写与回滚（[#20](https://github.com/yaodiff/memory-lab/issues/20)）

- 问题：批量改存量页的安全性取决于抽检和回滚。结论：说不清（做法有效，回滚没有系统演练）。
- [x] Task：让模型整批重写存量页，同时要求不升级、不降级、不删名字。结果：不行。错误率波动大，还悄悄删结构。放弃，改成加提示或程序化补丁。
- [x] Task：先抽检小批、设错误率门槛、过线再放量，写入前备份。结果：行。
- [x] Task：结构（章节、引用、标题形态）由程序校验。结果：行。
- [x] Task：门槛判定与写线上分属两条指令。结果：不行。已经写了才收到「未过线」。改为写进同一条任务，未过线默认不写。
- [ ] Task：#20 写一份回滚演练清单，在合成例子上演练一次。

## Issue：存量整理的保留与删除

- [x] Task：试用结论页替代原有细节页。结果：**Does not work**（内部小样本）。盲评仅约 2% 的分实体问题能从结论页获得所需的完整信息，试点已回滚。整理保留事实、证据、适用条件和复现所需细节，参见 [M3](m3-consolidation.md)。
- [x] Task：验证机器判删能否用于自动删除。结果：**Does not work**（内部小样本）。保守规则下一致率约 90%，放宽后约 40%–67%。机器只提供待审候选，删除由人工确认。
