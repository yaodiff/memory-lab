# M3 规范整合与去重

[← 总览](README.md) · [GitHub milestone](https://github.com/yaodiff/memory-lab/milestone/3)

## 目标与退出条件


- 目标：规范少而精、不重复、不矛盾，且不丢约束。
- 退出条件：整合方法的丢内容率和误合率在事先定好的门槛内。
- 状态：仅事件页冷藏已做生产分批，临时绕法改为人工定点补范围，规范整体退出条件仍待验证。

## Issue：夜间整理、冷藏与适用范围（[#99](https://github.com/yaodiff/memory-lab/issues/99)）

- [x] Task：[E034](../../experiments/E034-event-only-cooling-live/README.md)（内部小样本）。仅事件页冷藏后，在架事件页减少约 43%，试点验过原件及温层回找。
- [x] Task：[E037](../../experiments/E037-nightly-curation-readback/README.md)（内部小样本）。首个完整夜间整理窗口的复核未发现链接、摘要或触发词退化。
- [x] Task：[E042](../../experiments/E042-workaround-scope-review/README.md)（内部小样本）。关键词初筛的处置建议只约 14% 与人工完全一致。小批人工复核后才补适用范围，固定题整组找齐持平。
- [ ] Task：观察历史回执回找、默认检索和回滚，再决定是否夜间自动冷藏。继续人工复核高召回页的适用范围，保留正式约束和依据。

## Issue：按对去重还是按主题整合（[#23](https://github.com/yaodiff/memory-lab/issues/23)）

- 假设：规范集主要是碎片化而不是字面重复。结论：说不清（内部倾向按主题整合）。
- [x] Task：两两找相似并去重、允许拒绝合并的提示词。结果：不行。多数合并被回滚，因为是「同一对象的互补」。
- [x] Task：按主题整合，让整理模型能直接核对代码，矛盾以代码为准。结果：行。不核对代码的纯模型整合会留下过时分支。
- [x] Task：丢失比例拦截。结果：放弃。小块里比例失真，真丢的极少。
- [x] Task：试用结论页压缩同主题内容，并用分实体题目盲评完整覆盖。结果：**Does not work**（内部小样本）。完整覆盖约 2%，已回滚。整理保留能独立回答问题的原页和可核对出处，结论页用来导航。
- [ ] Task：#23 在合成碎片化规则集上比较两种方法的丢内容率和误合率。

## Issue：规范的准入门槛（[#24](https://github.com/yaodiff/memory-lab/issues/24)）

- 假设：把功能设计细节写成规范是规范集过大的原因之一。结论：说不清。
- [x] Task：提高门槛（跨任务、不知道就会做错、可执行可检查），不够格的转为决策。结果：行，规范数量下降。
- [x] Task：门槛按整页处理合并后的保留页。结果：不行。牵连被并入的条目一起被下线，已改为识别并排除保留页。
- [ ] Task：#24 在合成样本上测门槛的准确率与召回率。
