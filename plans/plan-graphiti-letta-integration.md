# Plan：把 Graphiti 与 Letta 的机制零件融进实体—关系记忆

## 背景与问题

[三系统调研](../docs/memory-systems-survey.md)（Refs #70）读完后，Graphiti 的时序知识图谱与 Letta 的分层记忆里有一批可拆解的机制零件。本计划只挑零件，不搬整套架构：完整图库的运维成本、以及让 Agent 自由改写核心记忆的做法，都与我们已有的小规模证据冲突。

我们自己的试点已经暴露四个具体问题，数字均来自小样本、只在本仓以粗粒度复述：

1. **LLM 直判又贵又不稳。** 实体去重目前直接上双模型判定，相当于只走 Graphiti 三级漏斗里最贵的第三级。一次全量盘点里原始一致率看起来很高，但剔除多数类效应后的 κ 只算中等；到页面级整理动作，一致率只有约三分之二、κ 接近随机水平。让模型只看特征做批量判断时，已知的同对象实体没有一对被自动识别出来；而独立复核又系统性地比原判更保守，几乎所有「双模型一致删除」的空壳都被救回。
2. **关系几乎没有出处。** 试点实体上原有的关系行里，只有大约百分之一带来源；按新规则让模型补写时可以做到逐条带来源，说明缺的是强制闸门而不是能力。
3. **常驻文件入口有用但会误用。** 对照实验里，搜索加上文件式记忆入口在「有明确实体或报错锚点」的题上优势明显（做对比例从约四成半升到约三分之二），但错页误采纳也明显更多；给每条记忆加上适用范围并要求采纳前核对后，误采纳大约减半，代价是做对比例小幅波动、区间包含持平。
4. **沿关系扩召回已经被证伪过一次。** E009（[#56](https://github.com/yaodiff/memory-lab/issues/56)）沿类型化关系扩一跳，结论是 Does not work：大约一半的漏召回没有可用起点，约三分之一有起点却与金标没有联系，重排还让更多错页进了前三。[#64](https://github.com/yaodiff/memory-lab/issues/64) 的独立实体栏是吸取该教训后的修正路线，本计划不重复这个方向。

另外要诚实界定收益边界：一次业务评测的丢分归因显示，大约六成丢分是「记忆里压根没有这条精确口径」，约两成是「读到了但没把事做完」，真正卡在召回环节的只是一小部分。这批机制治理的是记忆资产的长期可维护性与召回质量，不是缺知识和执行不完整的直接解药。

## 目标 / 不做什么

目标：

- 为八个候选融入点各写清现状、融入后的形态、要解决的已知问题与证据、代价和风险。
- 每个点配一个可离线验证的实验，判定线在开跑前冻结，沿用本仓「Works / Does not work / Inconclusive」三分法。
- 按性价比排序，只推荐一两个先做，并给出分阶段 timeline 和每个需要拍板的位置。

不做什么：

- 本轮不跑实验、不调模型、不动生产记忆和产品代码；这是方案阶段的交付。
- 不引入完整图数据库，不做 Agent 对记忆的自由直写，不重试 E009 已证伪的扩召回方式。
- 不在本仓放内部名称、原始数据、人员或链接；内部证据只以比例和粗粒度描述出现。

## 方案：八个候选融入点

### G1 三级去重漏斗的前两级（来自 Graphiti）

- 现状：双模型直接四档判定，无程序前置；特征级批量识别不出同对象。
- 融入后：在模型前加两道纯程序关卡——身份属性精确匹配（启动命令、代码目录、接口路径等归一化后相等）与名称归一化相似度（带名称熵值门槛，短名/通名词禁止自动并）。程序层只提名、不裁决，候选对仍走双模型与独立复核。
- 解决的问题：LLM 判定不稳且昂贵、自动合并命中为零。
- 代价风险：归一化规则与门槛需要维护；程序误匹配比漏匹配更危险，已知的同名不同对象反例要进硬黑名单；身份属性稀疏的概念类、指标类实体预期覆盖率低。

### G2 事实失效而不删除的结构化升级（来自 Graphiti，双时间轴缓做）

- 现状：旧页不物理删、降出默认搜索并在时间线标注取代，但取代信息只是正文文字，靠整理流程自觉。
- 融入后：把取代升级为页级结构化字段（继任者、生效时点、适用范围），校验继任页真实存在；检索命中旧页时显式提示「已被取代、现行口径见继任页」，而不是简单让它消失。矛盾判定拆成「是否重复」与「是否互斥」两问。
- 双时间轴：区分事实时间与系统记录时间能回答「当时系统相信什么」，但当前没有这类查询需求，维护成本不匹配，明确缓做，等出现历史时点回放需求再议。
- 代价风险：涉及页面结构与检索提示的生产改动；「不排除失效页」可能增加错页进前三，需要对照实测；同类设想在公开数据集上已得过一次 Inconclusive，本次判定线必须更硬。

### G3 关系来源的程序化校验（来自 Graphiti 与同类证据侧车实践）

- 现状：规范要求每条关系带来源，但存量关系行约只有百分之一合规，靠人工抽查。
- 融入后：来源指针由校验程序验证存在性，不合格的自动降为待核、不进导航；页面重写前后做引用数量核对，丢引用即放弃写入。不建完整的原始对话回链存储层。
- 代价风险：代码行号指针会随代码演进失效，需要配套复审触发；存量补来源有批处理成本；校验过严会频繁打断整理，需保留待核软通道。

### G4 按实体图扩召回：明确不做

E009 已证伪、#64 已接管修正路线，且存量关系来源完整度极低时扩召回只会放大错误关系。本计划不为它单开实验；重议条件是 G3 把关系质量提上去、#64 的实体栏实验出结果之后。

### L1 常驻核心记忆块的硬契约（来自 Letta）

- 现状：文件式常驻入口已验证有真实增益但误采纳更高；热层膨胀压力大，瘦身目标与现状差距很大，缺强制手段。
- 融入后：给热层块定字符与条目上限、根导览总预算；「先缩后长」——块满先清陈旧与可从代码重推的内容、细节降温层并留指针；每条要点强制带适用范围（这是我们已验证有效、Letta 反而没有的差异，保留）。准入仍走「未来用得上且代码看不出」双标准。
- 代价风险：上限是新超参，卡太狠会丢低频关键知识；加约束已观察到做对比例小幅下降的信号，实验必须同时看正确率与误采纳；瘦身依赖降层判定可信，与 G1 存在依赖链。

### L2 冷区触发词索引（来自 Letta deferred memory）

- 现状：降出默认搜索的页只保证可按 ID 读回，没有措辞友好的入口，降层约等于难以被发现。
- 融入后：每个降温主题在索引里留一行「遇到什么措辞的问题时该读回它」，用未来提问的语气写两三个说法，而不是写内容摘要。真实回放里已观察到「原词搜不到、换个说法就排第一」的系统性措辞偏差，这是该写法的实证依据。
- 代价风险：触发词本身由模型写，可能引入误导入口；措辞过宽会把冷层内容又拉回上下文、抵消瘦身；收益还取决于 Agent 是否真的愿意顺入口下钻。

### L3 出处下沉到版本记录（来自 Letta，折中方案）

- 现状：出处留在页内，可信直观但正文变长。
- 融入后：页内只留最短可用指针（脱离版本系统也能核验），冗长证据摘录下沉到独立证据侧车并由校验器保证指针存在；不采用「正文完全不出处」的极端做法，因为适用范围与出处信息已被证明能在采纳前拦住误用。
- 代价风险：与现行规范有直接取舍冲突，需修订规范；多一次读取跳转，在工具步数预算紧的任务里可能吃亏；历史版本读取通道的完备度需要先做接口确认。

### L4 Agent 自编辑工具：只借外壳，不放开自由写

- 现状：记忆变更走双模型加独立复核的收口，Agent 没有直写工具；页面级 κ 接近随机的证据支持这种保守。
- 融入后：只借两个外壳——字符串级精确替换的提案格式（替代整页重写，治「重写悄悄丢段落、误改邻页」的老毛病）与软删除标记；所有自编辑动作进待核队列，仍由现有收口裁决，不接生产直写。
- 代价风险：工程改动最深、离线只能验证提案质量验证不了长期效果；与夜间整理链路的职责边界要划清；排到最后做。


## 每个融入点的离线实验与判定线

统一口径：全部在我们冻结的内部离线评测集上做，开发组用于调参与校准，冻结回归组只在候选通过后跑一次终验。统一四个主指标——答案页前一/前三、登记错页进前三、下一步做对、误采纳，另记工具步数与上下文体积两个成本项。同题配对、重复随题保留，bootstrap 给配对差值的区间；判定线开跑前写进实验 issue，跑完不改线。下文样本量为目标区间，实际圈题后以冻结名册为准。

### G1 程序级去重前置（两阶段）

- 阶段 A 治理质量（主判定）：在冻结实体快照上跑两级程序关卡。对照是现行双模型跑批的既有结果。看三件事：已知同对象组的捞回比例（基线为零）、程序提名经复核确认的精确率、模型判定量的下降比例，以及残余疑难项的 κ 是否改善。
- 判定线：Works = 已知同对象捞回约四分之三以上、提名精确率至少九成、模型判定量下降约四成；Does not work = 捞回约四分之一以下或精确率低于七成半；其余为 Inconclusive。
- 阶段 B 检索非回归（守门）：把确认的合并投影到测试库，与基线快照同机同检索器对照受影响实体相关的检索题，目标不少于三十题（圈不够就如实标注样本不足）。前三命中不减少、错页进前三不增加才算通过。
- 预算：程序关卡零模型成本；模型复核量约为原全量跑批的十分之一量级，检索调用百次以内。整体最低。

### G2 结构化取代与命中提示（三臂）

- 臂：基线 / 结构化字段加命中提示 / 同结构但无提示（拆开字段化与提示各自的贡献）。
- 题集：涉及知识更新与新旧口径的题，包括合成知识更新题、带登记错页的检索题、含旧口径风险的行为题，目标检索二三十题、行为约二十题。
- 判定线：Works = 错页进前三相对下降至少三成且至少少一题，同时前三命中非劣（区间下界高于负两个百分点）；行为臂误采纳相对降至少两成且至少少一次，做对比例的区间包含零或为正。Does not work = 错页上升或做对比例明确变差。可判的误采纳事件太少（个位数以下）则 Inconclusive。
- 预算：中高，约百个行为试次量级；冻结组终验另算。若再得 Inconclusive，该方向暂停，不做第三次近似重复。

### G3 来源指针校验（两层）

- 层一（工具有效性）：校验器全量跑存量关系，分别报页指针与代码指针的存在性通过率；对试点关系行做盲态复核，给「指针真的支持这条关系」的语义通过率。语义通过率低于九成，校验器不合格，不进层二。
- 层二（行为对照）：基线库 vs 无来源关系降待核、重写页补齐指针的校验后库，目标不少于十五道行为题（圈不够就与 G1 阶段 B 合并共享回放成本）。
- 判定线：G3 主收益在治理侧，层二只要求无伤害——做对比例非劣（区间下界高于负五个百分点）且误采纳不增加即 Works；误采纳增加或做对比例明确变差为 Does not work；题量不足为 Inconclusive。
- 预算：低，校验器零模型成本，复核约十批，行为回放约六十试次。

### L1 热层硬契约（三臂）

- 前置标定（不占判定）：先观察实际被读热层块的体积分布，用实测分位取两三个候选上限做敏感性，不照抄任何外部系统的默认值。
- 臂：基线 / 预算裁剪臂 / 预算加适用范围臂。题集取开发组全部行为题主判，另用与降层页有关的检索题做非回归守门。
- 判定线：Works = 做对比例非劣（区间下界高于负三个百分点，比一般门槛更严，因为加范围字段已出现过小幅下降信号）且误采纳相对降至少两成、至少少一次，同时报热层实际净减比例。正确率降、误采纳也降且区间都覆盖零，记 Inconclusive。
- 预算：最高，全量行为题三臂两次重复达数百试次；历史同快照对照数据可部分复用，但正式判定以同快照重跑为准。可接受缩小题集的精简方案，需在拍板时定。

### L2 触发词索引（两臂）

- 题集不随机抽，定向取两类：金标页在默认搜索窗口之外或排名很靠后的检索题，以及已验证「换措辞即命中」的同构题，目标检索二三十题、行为十至十五题观察实际下钻。
- 判定线：Works = 目标检索题前三相对提升至少十个百分点（与 #64 增益线同值）且错页进前三至多增加两题；行为臂冷区目标页读到率至少六成且做对比例非劣。检索有效但 Agent 几乎不下钻（读到率低于三成）记 Inconclusive，机制可留作规范但不计行为收益。
- 预算：低，约六十个行为试次加少量模型抽检。

### L3 短指针加证据侧车（三臂）

- 臂：页内完整出处基线 / 短指针加侧车 / 正文完全不出处的极端对照（用来证伪全下沉，不实测不能下结论）。题集取要求实际读源回执的行为题与误采纳高发题，目标不少于二十题。
- 判定线：仅折中臂可能 Works——对口证据读到率非劣、工具步数中位数增加至多一步、误采纳不增加。读到率明确下降或步数超线为 Does not work；题量不足为 Inconclusive。
- 前置：先确认历史版本与侧车的读取通道可用；不通则取消极端臂、折中臂改本地文件模拟。
- 预算：中，约百二十试次。

### L4 字符串级变更提案（不接生产）

- 同一批整理任务两臂产出变更：整页重写式 vs 字符串级提案式。只看治理质量指标：引用丢失率、未声明邻页改动率、提案可机械应用率、盲态复核通过率，不跑评测分数。
- 判定线：Works = 引用丢失率降到零且邻页误改为零、复核通过率不低于基线（硬门槛，沿用已有教训）；任一破线即 Does not work；含引用页太少算不出稳定比率为 Inconclusive。即使 Works，也只得出「工具值得建」，建工具与接生产是另需批准的独立步骤。
- 预算：最低，无行为回放。

### G4

不设实验，理由见上节；重议条件是 G3 达标且 #64 出结果。

首批只推荐 G1 与 L1：分别打「写对」和「用得上」两个互不依赖的环节，都能在零生产改动下完成判定；执行上 G1 先行，因为 L1 的降层瘦身依赖可信的实体判定，而这正是 G1 要加固的。

预期管理：这些实验即使全部通过，改善的也是结构质量与召回侧的小比例丢分；「没有这条知识」和「有知识但没执行完」两类主要丢分不在本机制覆盖内，每个实验只对自己冻结的指标负责，不承诺评测总分涨幅。
