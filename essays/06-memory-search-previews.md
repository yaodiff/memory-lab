# 排序没变，Agent 为什么少用了记忆？

[English](06-memory-search-previews.en.md) · 中文

> 实践记录。线上观察和离线回放均来自小规模内部样本，只报粗粒度比例。文中的配置例子是合成的。

## 搜索结果也是 Agent 的输入

我们把团队记忆搜索结果里的正文预览换成生成式摘要。摘要让人容易看出一页在讲什么，但换了以后，**至少有一条返回页被采用的搜索占比，比之前低了约四分之一**。这里说的是搜索级占比的相对变化。一次搜索用了好几页也只算一次，分母是观察口径内的搜索。

先查统计口径，发现部分测试流量被错误计入了线上指标。修正后，首位采用率的降幅缩小。首位采用率只看同一次搜索的第一条有没有在同一会话被用上，和上面的「任一页采用」是两个指标。后面的线上拆解仍留有未解释的差距，无法把整段变化归给摘要。恢复正文预览后，答案质量大体回升，首位采用率的回升幅度较小，统计证据也不足。

这次和[三道关](01-three-gates.md)里的「找到了之后有没有照做」有关。中间还有一步值得测量：拿到搜索结果后，Agent 能看出哪条值得打开，或者直接看出哪条规则适用吗？

## 冻结排序，只换 Agent 看见的文字

回放给同一道题返回相同的页面和顺序，一组看生成摘要，另一组看正文预览。这样能把「换了哪几条、排在什么位置」从这个对照里排除。每个条件下，分母都是对应那一组的回放题，比例按题计算。

| 回放读数 | 生成式摘要 | 正文预览 |
| --- | --- | --- |
| 被判需要打开全文才能作答的题占比 | 约九成 | 约一半 |

这项读数衡量返回文本里的信息是否足够。模拟 Agent 无法打开全文，因此也测不到真实的打开率、补读成本，或读完以后能补救多少。回放只用了一个模型，每种条件只跑一遍。它提示文本本身可能卡住了决策，线上影响的大小仍要靠线上对照估计。

排序相同有一个直接的后果。只按页面标识和位置重算的首位命中率，两组必然相同。如果回归只测这项，两份响应会拿到同样的成绩，即使 Agent 能从其中一份读到适用条件，从另一份只能猜该打开哪页。

## 一段能用的预览要给什么？

设想一个合成场景。Agent 正给示例项目写配置更新工具，准备删除它不认识的键。两种返回文本指向同一页。

- 主题式摘要：「这份文档介绍配置更新的兼容性要求和测试方法。」
- 带证据的预览：「就地更新用户配置时保留未知键。显式重置才允许删除。修改写回逻辑后，用含未知键的配置跑一次读写往返测试。」

前一条能帮 Agent 选页。后一条还把当前行动需要的条件、例外和检查步骤送进了上下文。这一差别也有反方向的风险。只截出「保留未知键」会把规则错误地用在重置上。生成摘要和正文截取都会遇到这个问题。预览应该带可打开的来源，条件或例外无法在预算内呈现时，应标明需要读原文再决定。来源相互冲突时，先核对适用范围和版本。

## 把换预览做成可以验收的改动

先在开发集上比较正文预览、主题式摘要，以及保留条件和来源的证据型摘要。冻结题目、页面版本、候选顺序和每个位置的呈现预算，单独固定模型、工具配置和判定规则。开发集可以用来改模板，最后用按来源分离的留出集评估。先做只看预览的配对对照，再用相同的全文权限和阅读预算跑一轮。后者能看出损失能否补回来，以及补回来要多花多少次读取和多长时间。

| 层 | 记录什么 |
| --- | --- |
| 找到 | 有标注对口页的题里，对口页是否出现在结果里，排第几。固定排序时用它检查对照是否被破坏。 |
| 看懂 | 在有可用依据的题里，预览是否给出做决定所需的规则和条件。另记错误适用范围、过时结论和未经来源支持的断言。 |
| 补读 | 在允许打开全文的全部有效回放题里，有多少题打开了全文，读了几次，耗时多少。 |
| 用上 | 在全部有效回放题里，下一步是否符合任务要求。有规则的题看具体动作，无适用规则的题也检查有没有误用。 |

上线前先约定主指标和可接受的退化幅度。按题报告配对输赢和不确定区间，另外看必须读全文、容易错用规则、找不到依据的题。评分时隐藏组别，分歧回到证据和动作核对。随后用能隔离测试流量的线上对照看真实采用，并用动作抽样校验采用信号。若还没有这种对照，离线结果可以支持保留一个可靠的基线，线上收益仍是待测问题。

[Next-step Replay](../bench/next-step-replay/README.md) 提供了按决策点评估下一步的方法。换预览时，最终也应该问同一件事：规则已经出现在搜索结果里，Agent 最后有没有按它做对下一步？
